# 开发路线图

以下均是待实施工作。先维持当前可用原型，每步交付一个可回放的行为闭环；不把路线图当成功能已经实现的证据。

## P0：消息确认与归档（已实现；多人授权仍待实施）

输入队列承担待确认状态，消息、输入结果与世界状态同事务提交；玩家/NPC 共用 UUID 查重入口，迟到和失效成员在改变状态前拒绝。结束时捕获最终快照，覆盖同一步创建并结束。候选距离坐标已修正。具体机制与兼容在 [架构](architecture.md)。

已验收：真实处理器与持久化函数的离线场景覆盖重复/冲突提交、邀请未接通、非成员、过期 operation、离开后重入、最终回复和归档；本地 Convex 实际核对重复提交仅一条、迟到输入失败且无消息、归档消息数吻合。离线数据库边界是内存实现，不声称模拟了 Convex 事务故障；故障注入与公开身份授权另行验收。

## P1：两位 NPC 真实互聊

先做 Emma + Ben，不一次扩展全部角色。新增人物采用受控、可重复的追加操作：验证 world 与描述索引、避免同一配置重复创建，保持已有数据；已有身份变更单独迁移。随后为 Alex 保留扩展方式。

复用现有漫游、活动、邀请和双人对话。给两人不同兴趣与简单目标，先用规则控制背景频率和模型并发，不接 Jev。人类想找忙碌对象时显示状态并可取消等待；当前双人结构不支持直接加入两位 NPC 的对话，首版采用等对方空闲或发出稍后请求。

验收：无人主动聊天时，两位 NPC 走动、碰面、邀请、互相发言并结束；保存原句、参与者和时间。覆盖拒绝、忙碌、路径失败、模型超时和用户抢先交流，角色不会卡住。先离线确定性场景，再本机真实模型体验，记录每次会话调用量与延迟。

## P2：近期记忆（单 NPC 已实现；NPC 互聊追问待 P1）

recent/off 使用统一 MemoryPlugin.recall；recordConversation 复用真实归档与参与关系，无新记忆表、不请求嵌入或总结。本人/世界限定的原句作为不可信证据注入，保留来源，过滤旧记录，限制数量和字数。界面提供开关和原句来源。Emma 的同一次进入世界、跨会话偏好回忆已实测。

下一步：完成 P1 后验收 Emma 与 Ben 聊过 → 用户追问 Emma → 复述实际记录。第一版的转述就是带作者的对话原句，不推断远处谈话或全局共享知识。稳定玩家身份、语义检索和非对话事件来源均待后续需要再实现。

## P3：由经历影响活动与交流

先把兴趣、地点偏好和少量目标映射成有限规则。地图增加可辨认的广场、咖啡摊、河边座位，复用现有寻路；地图与角色数据都有更新旧世界的方案。过去的邀约只有双方确认、程序记录后才成为进行中目标；嘴上提议不等于已经约好。

验收：NPC 再次遇见用户或另一居民时，可以延续话题；能尝试前往相应地点，受忙碌、距离和超时约束；记忆查不到时仍可正常活动。先证明这条链路有价值，再决定是否用 Jev 取代规则。

## P4：可选 Jev 决策适配

依赖 P0～P3 的合法动作、事件与证据。另行核对 TypeSafe 当前接口、额度与 Key，不能将本项目 GLM Key 当作 Jev 凭据。

控制器按当前状态生成完整候选 ID，例如 `wait`、`continue_activity`、`walk_to_ben_at_cafe`、`invite_ben`，每个候选绑定目标、前提与过期条件。Jev 选择一个候选；程序验证返回值，执行前重新检查条件，完成后保存真实结果。另一个 NPC 独立决定是否接受。

调用由动作完成、收到请求、邀请或路径失效触发，不逐帧调用。GLM 继续生成台词；复杂目标提议也必须约束为已支持目标。超时、无法判断或返回无效 ID 时等待、追问或退回规则，不能凭置信度跳过合法性校验。

验收：100～200 条人工标注样本覆盖等价表达、否定、模糊请求、中英混用与识别错误；比较规则、GLM 判断接口和 Jev 的准确率、误动作、延迟与费用。随后回放邀请失效、目标忙碌和用户打断。评测证明收益后才作为默认决策方式。

## P5：英语反馈与语音

英语反馈先在文字界面做成可选回顾，保存原句、建议、交流目标、提示使用情况和具体证据；正确表达不强制改成模板。实时纠错与“先纠错再回应”提供开关，通过用户试用选择默认方式，避免每轮打断自由交流。

再接按键说话、转写、字幕、重听与语音合成。识别不清先确认文本，不误当语法错误；发音判断必须保留音频依据。输入优先于背景语音，打断后停止旧播放并使旧回调失效；不允许多个主要声音互相覆盖。

验收：一次体验有足够用户开口，语音打断与恢复可用；学习评价引用原句，区分独立完成、提示完成和换情境复用。延迟分段测量转写、决策、生成与合成；中位数 2.5 秒 / P95 5 秒只是初始目标，不声明已经达成。

## 公开多人服务的前置条件

此项可与本机能力开发并行，但在公开部署前完成：独立用户身份与 world 归属、每个读写入口的授权、人物 ID 与凭据绑定、消息和记忆隔离、模型并发与用量限额、日志脱敏、数据保留与删除。匿名 `Me` 和人数常量不能作为多用户上线依据。

验收：两个独立身份同时使用不串号、不越权；伪造 playerId/worldId 的请求被拒绝；重启恢复与限流行为有明确证据。正式部署指南仅在这些路径通过后补充。

## 现在开始的最小工作包

下一次编码做 P1 的第二位 NPC，与已有近期记忆结合验收 NPC 互聊后的追问。每次改动写清：涉及模块、一个完整场景、异常路径、离线回归与真实体验范围。P1 + P2 通过后，才得到用户想要的“他们聊过，我能追问”的最小产品。
