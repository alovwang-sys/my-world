# 验证与完成证据

## 现有检查

| 范围 | 命令 | 说明 |
| --- | --- | --- |
| 活动文档链接 | `npm run check:docs` | 本地文件目标检查；不访问网络、不校验锚点 |
| 定向离线回归 | `npm test -- --runInBand convex/aiTown/game.test.ts` | 示例：真实游戏输入与闲置退出，不调用模型 |
| 模型适配与历史注入 | `npm test -- --runInBand convex/util/llm.test.ts convex/agent/conversation.test.ts convex/agent/memory.test.ts` | 模拟外部边界，验证请求契约与记忆开关 |
| 全部现有离线测试 | `npm test -- --runInBand` | 涉及多个核心模块或共享契约时运行 |
| 编译与产物 | `npm run build` | TypeScript 与 Vite；不能替代后端部署和浏览器验证 |
| 静态检查 | `npm run lint` | 当前有上游遗留诊断，区分新增与既有问题 |
| 真实模型 | `npm run check:models` | 手动付费网络检查；前提见 [开发指南](development.md) |

只改文档运行文档检查；修改前端行为还需构建与浏览器操作；改变引擎、消息或数据契约补对应真实路径回归，再扩大到共享受影响模块。不要因为临近提交而重复已经通过且未受新改动影响的检查。

当前项目没有已接入的 CI 文档检查、完整会话回放、自动浏览器测试或 Jev 评测脚本。消息可靠性场景在 [reliability.test](../convex/aiTown/reliability.test.ts)，使用真实游戏/提交/归档/检索逻辑与内存数据库边界；模型请求证据断言在 [conversation.test](../convex/agent/conversation.test.ts)，确认订阅清理在 [sendInput.test](../src/hooks/sendInput.test.ts)。表中的命令是本地已有工具；未来新增项见 [路线图](roadmap.md)。

## 浏览器验收

单 NPC 交互：加入 → 地面移动、平移缩放、找到我 → 选居民定位 → 走近与邀请 → 接通、发言与连续回答 → 离开 → 再选同人查看历史。验证中文输入法、Enter、Shift + Enter、发送失败草稿、重复发送保护、阅读历史不强制滚动以及窄屏布局。

异步与计时：用户输入成功才刷新活动时间；NPC 后台回答不延长用户闲置。关闭对话、换人、卸载或超时后，迟到的结果不应改变当前会话。消息确认与迟到结果路径已增加回归；登录授权、多人和完整故障回放仍需单独验收。

使用真实模型时记录请求模型、返回模型、正文是否存在和耗时。检查前确认当前部署与费用范围；不要让普通构建、单测或页面截图任务触发真实 API。

## 后续开发采用的回放约定

这是下一阶段需要实现的测试方法，当前没有对应运行命令。借鉴 DeepSeek Harness：保留真实输入路径，替换模型、网络、时间和随机性等外部边界，断言最终状态与持久化内容，不能只检查 NPC 自称完成。

每个重要场景至少保留：初始世界及 schema 版本、按顺序的用户与 NPC 输入、可控时间和随机源、脚本化模型响应或错误、预期消息与世界状态。模型回放匹配具体请求的角色、历史与候选动作，未知调用直接失败，不能用永远返回“成功”的 mock。

多人场景需要核对实际参与者、开始/结束、消息作者、对象位置和下一次读取的记忆来源。异常场景覆盖超时、拒绝、忙碌、无法到达、重复回调、用户离开和重启；取消后的文本不得进入有效消息或记忆。敏感真实对话不作为公开 fixture。

首次实现先使用现有 Jest 和脚本化适配器，场景文件就近放置。不要复制 Harness 的 JSONL 协议、覆盖率制度和整套快照框架；需要持久化请求日志时另行设计兼容与保留策略。

## 交付证据格式

```text
版本：提交 SHA 或工作树改动范围
环境：Node / 部署类型 / 关键开关，不含 Key
行为：用户或 NPC 的实际输入
预期：消息、位置、会话成员、记忆来源等可观察结果
验证：实际运行命令与结果，或浏览器操作与结果
限制：未运行的真实 API、多人场景、平台或学习效果
```

一次 API 成功不代表多人链路成功；一次完整交流不代表掌握表达。当前验证基线集中在 [产品文档](product.md)，后续只在发生新验证时更新，避免改文档时刷新证据日期。
