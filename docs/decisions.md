# 设计与开发决策

## D5：回复失败及时结束并允许重试（2026-10-04）

状态：已实施。81 个离线测试、构建和真实模型回复通过；本地关联失败输入注入后，页面提示与重试恢复通过，用户原消息只保留一份。

问题：模型连接发生 TLS 握手失败时，消息已保存，但回复 operation 要等 120 秒超时才释放，前端没有失败结果。

决定：复用现有网络退避，聊天各次请求共用 90 秒预算；网络 TypeError 可退避重试。生成失败通过关联 operation / 会话 / UUID 的内部输入释放状态，显示安全的回复错误；用户可重试回复或继续发新消息。重试不复制用户消息，错误不写进消息或记忆。截止时间兜底也显示错误。新字段可选，旧会话继续兼容；不切换模型或清理历史。

## D4：确认消息与可切换的近期记忆（2026-10-03）

状态：已实施。消息与归档的离线回归、本地实际重复/迟到提交验证、真实模型跨会话偏好回忆通过。

用户行为：与 Emma 聊过偏好，结束对话后再追问；能开关回忆并查看原句来源。

决定：待确认文本只进入现有 inputs，合法发言与输入结果、世界变化在 saveWorld 的同一事务提交。按世界 / 会话 / UUID 查重；结束时显式捕获最终会话快照，避免同一步创建并结束或旧快照丢消息。新版消息与归档以 confirmationVersion=1 标记，旧历史不删除，也不自动升级为可信证据。

记忆 recordConversation 复用会话归档和参与关系，recent/off 实现统一 recall 契约；关闭只影响历史供给，不停止存档。首版不新增记忆表、不总结、不请求嵌入。范围限定本人、世界与近期原句，截断保留标记。单 NPC 会话内身份沿用已有 playerId，退出世界重新加入的持久用户身份仍待实现。

失败路径：失效会话、成员不符、过期 operation 在改变状态前拒绝；网络确认未知时保留正文和 UUID，重试查原结果；记忆查询失败与没有记录分别表达。沿用匿名本机原型的部署边界，不声称这些校验提供登录用户授权。

只记录影响后续开发的持久取舍。当前机制在 [架构](architecture.md)，未来工作在 [路线图](roadmap.md)。局部样式和机械改动不单独建记录。

## D1：AI Town 继续作为底座

状态：已采纳。

问题：从零制作地图、移动、人物调度与持久化会挤占社交体验验证时间。

决定：保留 React、PixiJS、Convex 和现有引擎，在已有 operation、输入处理器、会话与模型适配层扩展。用户自由参与是主体验，场景任务可选。

取舍：复用现有能力，但接受双人会话、已有数据契约和初始化限制；多人群聊与订单系统需要另做设计。改造前检查现有职责，避免为了未来动作一次建立通用世界引擎。

## D2：先使用原句支持近期社交记忆

状态：已实施单 NPC 近期回忆；NPC 互聊追问仍待路线图 P1 / P2。

问题：当前嵌入访问受限，而跨会话追问需要准确来源，不能等长期向量服务全部完善。

决定：先复用参与关系、档案与消息索引，给 NPC 提供本人近期、有限且有来源的原句。事件事实、转述、看法与计划分开；未来摘要也是派生内容，不能覆盖原始证据。

取舍：直接查询容易核查，范围有限，也不擅长模糊语义检索。只有真实使用证明需要时再接向量与摘要；消息有效性必须先通过 P0 验收。
